# 티칭로그 AI 서버 (FastAPI) — 모델: claude-haiku-5-5 하나

AI 파트 API 명세(AI-0 ~ AI-9)와 ERD에 맞춘 AI 서버입니다. Django만 부르고, DB를 쓰지 않습니다. 요구사항 전체는 `티칭로그_AI서버_PRD_v1.12.pdf`에 있습니다.

```
프론트엔드 ──▶ Django ──(X-Internal-Token, X-Request-ID)──▶ AI 서버 ──▶ Anthropic Claude
```

## 0. 모델

**모든 기능이 `claude-haiku-5-5` 하나를 씁니다** (PRD 4-3). 기능마다 모델을 나누지 않습니다.

- 단 하나의 차이: 수업 중 용어 판정(AI-3 judge)만 같은 모델을 깊이(effort) `high`로 부릅니다. 체크리스트가 맞게 체크되는지가 가장 중요해서입니다. 나머지는 모델 기본 깊이(medium)입니다. 더 비싼 모델을 부르는 것이 아니라 같은 모델에 "더 깊이 생각" 설정만 붙인 것이라 단가는 같고, 생각에 쓴 토큰만큼 비용·시간이 조금 늘어납니다 (팀 결정: 유지).
- 코드 안의 `light` / `deep` / `judge`는 **나중에 일부 기능만 모델을 바꿀 수 있게 남겨 둔 설정 칸**일 뿐, 지금은 셋 다 같은 모델입니다. 바꿀 일이 생기면 `.env`에 `MODEL_LIGHT` / `MODEL_DEEP` / `MODEL_JUDGE`를 한 줄 추가합니다 (9장).

| 설정 칸 | 들어 있는 기능 |
| --- | --- |
| `light` | 자료 쪽·이미지 읽기, 손 들기, 학생 질문, 정리노트, 학생 문제 풀이, 성장보고서 문장 |
| `deep` | 용어 체크리스트, 요약정리·관계, 출제·정답 검사, 주관식 채점 |
| `judge` | 수업 중 용어 판정 (effort high) |
- 비용이 가장 적은 구성입니다. 한 번에 보내는 입력이 10만 토큰을 넘으면 Haiku 5.5 단가가 5배가 됩니다 (보통 수업에서는 넘지 않음).

## 1. 실행

환경 변수 3개가 필요합니다. 로컬에서는 프로젝트 폴더에 `.env` 파일을 만들어 아래처럼 적고, 배포 서버(Render 등)에서는 대시보드의 환경 변수 칸에 같은 이름으로 넣습니다.

```bash
APP_ENV=local                 # 배포할 때는 prod
ANTHROPIC_API_KEY=sk-ant-...  # Anthropic Claude API 키
AI_SERVER_TOKEN=...           # Django와 같은 값 (X-Internal-Token). local에서 비우면 인증 생략, staging/prod는 필수
```

```bash
pip install -r requirements.txt
python scripts/check_llm.py # 키와 모델이 연결되는지 확인
uvicorn app.main:app --host 0.0.0.0 --port 8001 --no-access-log
```

- 포트 `8001`: 로컬에서 Django가 8000번을 쓰므로 AI 서버는 8001번으로 켭니다. Django `.env`의 `AI_SERVER_URL=http://127.0.0.1:8001`과 맞춘 값입니다.
- Django `.env`의 `AI_SERVER_TOKEN`은 이 서버 `.env`의 `AI_SERVER_TOKEN`과 **같은 값**이어야 합니다. Django는 토큰이 비어 있으면 AI 서버를 부르지 않고 `AI_SERVER_NOT_CONFIGURED` 에러를 냅니다.
- `--no-access-log`: 요청 로그는 서버가 직접 `http_request` 이벤트(JSON)로 남깁니다.
- Render 같은 배포 서버에서는 포트를 `--port $PORT`로 바꿉니다 (Docker 없이 배포).
- API 문서: `/docs` (`APP_ENV=prod`에서는 꺼짐. 배포 서버에서 Swagger로 시험하려면 그 서버를 `APP_ENV=staging`으로 띄우세요. staging도 `AI_SERVER_TOKEN`이 필수라 Swagger의 `X-Internal-Token` 칸에 토큰을 넣어야 합니다)

| AI-7 | `POST /exams/solve` | student | light | 170초 |

## 3. AI 파트가 정하기로 한 값

| 항목 | 값 | 설정 |
| --- | --- | --- |
| 용어 개수 (AI-1) | 자료 길이로 정하지 않고, AI가 **핵심 용어만** 고름 (**3~10개**). 핵심 기준: 자료가 직접 정의·설명함 · 빼면 수업에 구멍이 생김 · 서로 겹치지 않음. 견주어야 뜻이 생기는 짝 개념은 `A·B` 한 줄로 합침 (예: `전역 최솟값·지역 최솟값`, 둘 중 한쪽 이름만 말해도 그 용어를 말한 것으로 봄). 함수·인수 이름, 예시 속 단어, 수식 기호는 제외 | `MIN_TERMS`, `MAX_TERMS` |
| 평가 문제 (AI-6·AI-7, 학생 AI가 풂) | **5문항** (팀 확정 2026-11-11). `question_types: ["multiple_choice", "short_answer"]` → 객관식 3 + 주관식 2. 실측(용어 3개, 10문항으로 잼): AI-6 28.5초·58.8초, AI-7 11.0초·12.9초라서 5문항이면 170초 안에 충분히 끝남 | Django가 보내는 `count` |
| 재시험 문제 (AI-6, 사용자가 풂) | **3문항** (팀 확정 2026-11-11) → 객관식 2 + 주관식 1 | Django가 보내는 `count` |
| 쌓을 수 있는 손 든 표시 | 제한 없음 (기능명세서). 필요하면 개수 제한 가능 | `MAX_RAISED_HANDS` (0 = 제한 없음) |
| 손 들기 판단 시점 (AI-3) | 설명이 한 단락 끝난 때만 판단: 새 용어로 넘어감 · "알겠지?/질문 있어?/정리하면" 같은 넘기는 말 · 학생 질문에 답함, 이 세 시점에만 판단 (팀 결정). 같은 주제를 이어서 설명하는 중에는 판단하지 않음. 설명 도중(":", "그리고", "-고/-서/-면"으로 끝남)이나 짧은 맞장구면 손 들기 LLM을 부르지 않음 (`hand_raise: null`). 한 시점에 막힌 게 있으면 같은 주제에서도 여러 번 들 수 있음 | `app/services/lesson.py`의 `hand_raise_point` |
| `explained` 기준 | **용어 언급 + 간단한 설명**이면 체크 (팀 결정). 정의 전체를 말하지 않아도 핵심을 맞게 말하면 되고, 정의를 그대로 옮겨 적어도 인정. 틀리게 설명하면 `mentioned`. 이름 없이 내용만 설명하면 체크 안 됨 (A안) | `REQUIRE_TERM_NAME_FOR_EXPLAINED` (true/false) |
| 페르소나 `system_prompt` | `app/personas/personas_seed.json` (haneul, minjun, seoyeon, hyunwoo=정현우 교수님). 모든 페르소나 뒤에 공통 학생 규칙 `app/prompts/student_rules.md`가 붙음 | Django `personas` 시드 (**예시 문장이 바뀌어 다시 시드 필요**) |
| 업로드 상한 (AI-1·2) | **20MB, PDF 50쪽 이하** (팀 확정) | `MAX_UPLOAD_MB`, `MAX_PDF_PAGES` |
| 정리노트 구성 (AI-5) | **개념 설명 · 질문과 답 · 아직 궁금한 사항** (팀 확정). 예시 설명 칸은 따로 두지 않음 (예시는 개념 설명 안에 들어감) | `app/services/note.py` |
| 페르소나 글투 | 학생이 화면에 쓰는 모든 글(질문 AI-4, 정리노트 AI-5, 시험 주관식 AI-7)에 **그 페르소나의 글투만** 붙임. 하늘: 쉬운 말·"\~래요!"·감탄 / 민준: "A = B", "→ 그래서", "제 말로 하면" / 서연: 개조식 "\~함/\~임", "vs", "단," / 교수님: "정의 —", "(선생님 설명 기준)", "※ 조건 미확인". 정리노트는 글투 표시가 너무 적으면 코드가 다시 부름 | `app/personas/voices.json` (AI 서버에 있으므로 Django 재시드 불필요) |
| 학생 반응 (AI-3) | 선생님이 **학생 질문에 답했을 때만**, 다시 손 들지 않았으면 페르소나별 **고정 문장** (LLM 호출 없음, 팀 확정) | `app/personas/reactions.json` |
| 성장보고서 구성 (AI-9) | 잘한 점 · 놓친 개념 · 복습 추천 (못한 점 없음). AI는 잘한 점·복습 추천 문장만, 놓친 개념은 Django가 체크리스트 상태로 계산. 문장의 주인공은 사용자(선생님)의 설명 | Django·프론트 |

- 문제 수를 줄인 이유: 요약정리에서 근거로 쓸 줄이 문제 수보다 적으면 **같은 사실을 여러 문제가 말만 바꿔 묻게 됩니다** (코드가 막는 중복은 똑같은 문장뿐). 실측(용어 3개, 10문항): 요약 12줄이면 10문제가 모두 다른 줄을 근거로 썼지만, 요약 6줄이면 한 줄을 3문제가 근거로 써서 그 사실 하나로 30점이 오갔습니다.
- 재시험 용어가 1개이고 그 용어의 요약 줄이 2개뿐이면 3문항 중 2문항이 같은 줄을 쓸 수 있습니다 (이 경우는 아직 실측 안 함).
- 유형은 `question_types` 순서대로 번갈아 냅니다. `question_types`는 **최대 2개**(유형 수)라서 지금은 한 유형만 또는 반반만 됩니다. 7:3 같은 다른 비율은 AI 서버 변경이 필요합니다 (미정).
- 용어는 `term_id`를 차례로 돌며 배정합니다 (재시험이면 `focus_term_ids`만). 요약정리에 내용이 없는 용어는 빠집니다. `focus_term_ids`에 `terms`에 없는 id가 있거나, 지정한 용어가 모두 요약정리에 없으면 `422 VALIDATION_ERROR`입니다 (전체 용어로 바꿔 내지 않음).

## 4. Django가 알아둘 점

- **객관식 정답·답은 보기 인덱스(0부터) 문자열**입니다. 재시험에서 사용자가 낸 객관식 답도 같은 형식으로 비교하세요. 학생 AI(AI-7)의 객관식 답도 숫자 하나(`"2"`)로만 옵니다 (말투는 주관식에만).
- 정리노트(AI-5)는 **페르소나 글투**로 쓰입니다 (하늘 "\~래요!", 민준 "A = B → …", 서연 개조식 "\~임", 정현우 교수님 "정의 — … (선생님 설명 기준)"). 선생님이 한 말은 틀리거나 짧아도 빠짐없이 들어갑니다 (수업 예고 문장 "오늘은 \~ 배울 거야"는 빠질 수 있음).
  - 노트는 세 부분입니다: `## 개념 설명`(설명 메시지, 주제별 `### 1. 소제목`) → `## 질문과 답`(`### Q1. 학생 질문 원문` + 선생님 답을 정리한 줄) → `## 아직 궁금한 사항`. 비어 있는 부분도 제목과 안내 문장("수업 중에 주고받은 질문이 없어요." 등)은 나옵니다.
  - **요청에 `raised_reasons`(선택, 기본 `[]`)가 추가됐습니다.** 손은 들었지만 선생님이 수업 끝까지 누르지 않은 이유를 AI-3 때와 같은 형식으로 보내면 '아직 궁금한 사항'에 페르소나 말투로 들어갑니다. 안 보내면 그 부분은 '답을 못 받은 학생 질문'만 나옵니다.
  - 답변은 `reply_to_id`로 질문과 짝을 짓습니다 (없으면 바로 앞의 짝 없는 질문). 한 질문에 답을 여러 메시지로 나눠 보내도 같은 Q 아래에 모입니다.
- **질문받기를 했으면 선생님은 항상 답을 한다고 봅니다 (팀 결정 2026-11-11).** 학생 질문 뒤에 오는 첫 선생님 메시지는 `kind: explanation`이고 `reply_to_id`가 없어도 AI 서버가 그 질문의 답변(`answer`)으로 바꿔 읽습니다 (AI-3·4·5·7·9 모두, `app/schemas/api.py`의 `link_answers`). 질문이 여러 개 쌓였으면 최근 질문부터 답한 것으로 봅니다. 그래서 '아직 궁금한 사항'의 '답을 못 받은 질문'은 질문 뒤에 선생님 메시지가 하나도 없이 수업이 끝난 경우뿐입니다.
  - Django가 지금 프론트에서 `reply_to_id`를 받을 때만 `answer`로 저장하는 것은 그대로 두어도 됩니다. 프론트가 `reply_to_id`를 보내 주면 짝이 더 정확해집니다 (질문이 여러 개일 때).
- AI-3 응답에 **`reaction`(문자열 또는 null)이 추가됐습니다.** 방금 메시지가 학생 질문에 대한 답(`kind: answer`)이고 학생이 다시 손 들지 않았으면 페르소나별 고정 문장이 옵니다 (예: 하늘 "아하! 이제 알겠어요!"). 그 밖에는 `null`. 채팅에 학생 말풍선으로 보여 주되, 수업 대화(`messages`)에는 저장하지 마세요 (저장하면 학생 kind에 없는 값이 됩니다). Django에서 새로 만든 페르소나는 공통 문장을 씁니다.
- **평가와 재시험의 문제 수가 다릅니다 (평가 5, 재시험 3).** AI-6 요청의 `count`를 시험 종류마다 따로 보내 주세요. 설정 하나(예: `EXAM_QUESTION_COUNT`)를 두 시험에 같이 쓰면 안 됩니다.
- 학생 질문(AI-4)은 항상 질문 하나(물음표 하나)입니다.
- 학생 AI가 모르는 문제는 `"모르겠어요. 수업에서 안 배웠어요."`로 답합니다 (주관식이면 AI-8이 코드로 바로 틀림 처리).
- AI-8은 요청에 평가/재시험 구분이 없어서 **문항이 1개면 실시간(25초), 여러 개면 백그라운드(170초)** 예산을 씁니다. 평가인데 주관식이 1개뿐이어도 25초 안에 끝나므로 문제는 없습니다.
- 에러는 명세의 5개 code만 씁니다. 예상하지 못한 서버 오류도 `502 LLM_ERROR`로 돌려주고, 원인은 `exception` 로그에 남깁니다.
- 로그는 명세의 이벤트(`http_request`, `llm_call`, `llm_invalid_output`, `exception`)와 필드만 씁니다. 실패 원인은 공통 필드 `message`에 들어갑니다. 그 밖의 자세한 기록은 `DEBUG`라서 `local`에서만 찍힙니다.
- AI-1과 AI-2는 명세대로 같은 파일을 각각 받습니다. 다만 AI가 이미지로 읽은 쪽(그림·깨진 글자·사진)은 AI-1에서 읽은 결과를 서버 메모리에 잠깐 기억해 두고 AI-2에서 다시 씁니다 (5장). 실측 RNN 30쪽: AI-2 51~80초 → 25초.
  - Django는 **AI-1이 끝나면 15분 안에 같은 파일로 AI-2**를 부르면 됩니다 (지금 흐름 그대로). 늦거나 서버가 재시작됐으면 다시 읽을 뿐 결과는 같습니다.
- `AI_SERVER_TOKEN`이 비어 있으면 `APP_ENV=local`에서만 인증을 생략하고, staging·prod에서는 모든 요청을 401로 막습니다. **배포할 때는 반드시 `APP_ENV=prod`와 `AI_SERVER_TOKEN`을 설정하세요.**
- `.env`(API 키)는 압축 파일·깃·메신저로 공유하지 마세요. `.gitignore`에 들어 있습니다. 키가 밖에 나갔다면 콘솔에서 바로 재발급하세요.
- 입력 상한: 업로드 `MAX_UPLOAD_MB`, 메시지·문제·답·보기·용어 정의 1개 10,000자, 이름·제목 200자, 페르소나 `system_prompt` 20,000자, 대화 400개, 용어 50개, 문항 30개, 보기 10개. 넘으면 `422 VALIDATION_ERROR`.
  - 업로드 크기 검사는 요청 본문을 다 받은 **뒤에** 합니다 (FastAPI·Starlette는 엔드포인트가 실행되기 전에 본문 전체를 받아 둡니다). 그래서 아주 큰 업로드를 받는 순간부터 막으려면 **앞단 프록시에서 크기를 제한**하세요. 예: nginx `client_max_body_size 21m;` (`MAX_UPLOAD_MB` + 여유 1MB).
- AI-9는 `exam.total` = 문항 수, `exam.correct` = `is_correct: true` 수가 맞지 않으면 `422 VALIDATION_ERROR`입니다. `is_correct: null`(채점 안 됨)인 문항이 있으면 `correct`가 'true 수 ~ true 수 + null 수' 사이인지 확인합니다.
- LLM 동시 호출은 `LLM_GLOBAL_CONCURRENCY`(기본 8)로 묶입니다. 차례를 기다리다 시간 예산을 넘으면 `504 LLM_TIMEOUT`.
  - 이 상한은 **서버 프로세스 하나 기준**입니다. 위 실행 명령(프로세스 1개)이 권장 구성입니다. `--workers N`으로 여러 개를 띄우면 전체 상한은 N × 값이 되므로, 전체를 8로 두려면 값을 `8 ÷ N`으로 낮추세요 (여러 서버에 걸친 공유 제한이 필요하면 Redis 같은 별도 장치가 필요합니다).
- `llm_invalid_output` 로그의 `raw_output`(AI 응답 앞 2,000자)은 **명세의 로그 규칙**이라 기본으로 남깁니다. 이 안에 자료·대화 일부가 들어갈 수 있으니, 운영 로그 보관 기간과 접근 권한을 제한하세요.
  - 팀에서 운영 로그에 원문을 남기지 않기로 정하면 `.env`에 `LOG_RAW_OUTPUT=false`를 넣습니다. 필드 이름은 그대로 두고 값만 `[생략: 1234자]`로 바뀝니다 (명세 로그 규칙도 함께 고치세요).
- 업로드 파일: Starlette가 1MB를 넘는 업로드를 받는 동안 **디스크 임시 파일**에 잠깐 저장하고, 요청이 끝나면 지웁니다 (우리 코드가 아니라 프레임워크 동작). 그 뒤 처리(PDF를 이미지로 바꾸기, 이미지 줄이기)는 메모리에서만 하고 따로 파일을 만들지 않습니다. PDF는 `with`로 열어 오류·시간 초과 때도 닫힙니다.
- LLM에 보내는 이미지(사진 업로드, 그림이 있는 PDF 쪽)는 긴 변을 1,568px 이하로 줄여 보냅니다. 이미지 형식은 확장자가 아니라 파일 앞 바이트로 판별하고, PNG·JPG가 아니면 `422 UNREADABLE_MATERIAL`입니다.
- PDF의 쪽 분석·렌더링(LLM 호출이 아닌 CPU 작업)도 요청 시간 예산 안에서 합니다. 넘으면 `504 LLM_TIMEOUT`.

## 5. 자료(PDF) 읽기

쪽마다 상태를 코드로 판단해서 읽는 방법을 다르게 합니다 (판단에는 LLM을 쓰지 않음).

| 쪽 상태 | 판단 | 읽는 방법 |
| --- | --- | --- |
| 정상 | 아래 두 경우가 아님 | 글자만 뽑음 (LLM 호출 없음) |
| 그림 있음 | 이미지가 있거나, 도형 수가 보통 쪽보다 확실히 많음 (로고·메뉴 막대처럼 모든 쪽에 있는 것은 제외) | 글자는 그대로 쓰고 그림 안 글자 조각은 뺌 → AI가 쪽 이미지를 보고 `[그림: …]` 설명을 덧붙임 |
| 글자 깨짐·스캔본 | 한국어에서 흔한 글자 비율이 아주 낮거나 겹받침 글자가 많음 (글꼴에 글자 정보가 없는 PDF), 또는 글자가 거의 없는데 그림이 있음 | 쪽 전체를 AI가 이미지로 읽음 |

- 위·아래 가장자리(15%)에서 절반 이상의 쪽에 반복되는 줄(머리말·꼬리말·메뉴 줄)과 쪽 번호(`17 / 35`)는 지웁니다.
- 이미지로 읽을 쪽은 `PAGES_PER_READ`(기본 4)쪽씩 묶어 한 번에 보내고, 묶음끼리는 동시에 보냅니다. 해상도 `PDF_RENDER_DPI`(기본 130).
- PDF는 `MAX_PDF_PAGES`(기본 50)쪽 이하.
- **읽은 결과 캐시** (`app/rag/read_cache.py`): AI가 읽은 쪽이 있으면 그 결과를 파일 내용의 SHA-256을 열쇠로 메모리에 둡니다. 디스크에 쓰지 않고, 15분 뒤 또는 AI-2가 성공하면 바로 지웁니다 (원본 폐기 원칙). 최대 16개, 서버 프로세스마다 따로입니다.
- **한계**: 이미지로 읽은 글은 원본 글자와 대조할 수 없어서, AI가 잘못 읽은 글자는 검증으로 잡히지 않습니다.

## 6. 호출 제한(429)

- 호출 제한·일시 오류는 공급자가 알려준 시간만큼(없으면 4·8·15·25초) 기다렸다가, **요청의 시간 예산 안에서만** 다시 부릅니다. 기다리면 예산을 넘으면 바로 `502 LLM_ERROR`.
- 이 재시도는 명세의 '형식이 틀리면 한 번 다시 부르기'와 별개입니다 (응답 자체를 못 받은 경우에만).
- AI-2는 용어별 RAG 검색은 따로 하고, 요약은 용어 3개씩 묶어 동시에 부릅니다 (10개면 요약 4번 + 관계 1번). 한 번에 10개를 부르면 출력이 1만 토큰을 넘어 max_tokens에서 잘렸습니다. 응답이 잘리면 "더 짧게"를 붙여 한 번 다시 부릅니다.
- AI-2 용어당 요점은 2~4개가 목표지만, **자료에 근거가 확인되는 만큼만** 씁니다 (팀 결정). 자료가 얇아 처음부터 1개면 그대로 두고, 검증에 떨어져 2개 미만으로 줄었을 때만 다시 부릅니다. 0개면 한 번 더 요약하고, 그래도 없으면 정의 줄만 둡니다.
- Claude는 결제한 계정의 사용량 한도(분당 요청·토큰)를 따릅니다. 429가 나면 Claude Console에서 한도를 확인하세요.

## 7. 할루시네이션 대책

| 장치 | 막는 것 | 적용 |
| --- | --- | --- |
| Enum + 엄격한 JSON Schema | 목록에 없는 상태값(`todo/mentioned/explained`, 문제 유형 등), 빠진 필드 | 모든 LLM 호출. 공급자 쪽 강제 + Pydantic 재검증 |
| RAG (BM25, 외부 임베딩 없음) | 자료와 무관한 사전 지식으로 요약하는 것 | AI-2 요약정리 (용어마다 관련 청크만) |
| **원문 인용 검증** | 지어낸 근거. 인용이 자료·대화·요약정리에 실제로 있어야 통과. 8자 이상(원문이 짧으면 원문 전체, 또는 4글자 이상 문장 하나 전체), 20자 미만은 글자 그대로만, 비슷하게만 맞으면 부정어(않·못·없·아니·안) 수가 같아야 통과 | 용어 정의, 요약 문장, 관계, 용어 판정, 정리노트, 출제, 학생 풀이, 잘한 점 |
| **본문 검사 (LLM)** (`verify_claims`) | 인용은 진짜인데 본문은 다른 말을 하는 것 (뜻 뒤바뀜, 원인·결과 뒤바뀜, 없는 내용 보탬, 숫자를 다른 대상에 붙임). 만든 AI와 별개인 호출이 '근거만으로 이 문장이 나오는가'를 보고, 떨어진 항목은 이유를 붙여 다시 부름. 학생 쪽은 사실 여부가 아니라 '선생님이 그렇게 말했는가'를 봄 (틀리게 배운 내용은 통과) | AI-2 요점·관계(근거 청크), AI-5 노트 줄·AI-7 답(선생님 메시지) |
| 숫자 대조 (코드, `numbers_unsupported`) | 근거 원문에 없는 숫자(두 자리 이상·소수). LLM이 약한 부분이라 코드로 한 번 더 | AI-1 정의, AI-2 요점·관계, AI-5 노트 줄, AI-7 주관식 답 |
| **정의 독립 검사** (LLM) | 인용은 진짜인데 다른 개념·식·예시를 정의로 가져온 것 (예: '학습률' 정의로 업데이트 식), 뜻이 뒤바뀐 정의 → 떨어진 용어는 이유를 붙여 추출을 다시 부름 | AI-1 |
| 질문 검사 (`unheard_terms` 등) | 물음표가 두 개 이상인 질문, 수업에 없던 기호·표기(`h_t` 등), 수업·페르소나 '원래 아는 것'에 없는 영문 용어(LSTM 등) → 다시 부름. 한글 낱말은 글자 비교라 평범한 말('줄어드는')도 걸려서 기록만 남김. 마지막 시도에서도 남으면 질문은 돌려줌 (오탐으로 버튼이 실패하지 않게) | AI-4 |
| 번호·ID 검증 | 없는 청크·메시지·줄 번호·term_id | 전부 |
| 정답 독립 검사 | 출제 AI가 정답을 잘못 단 문제 | AI-6 (통과한 문제만 사용) |
| 코드가 정하는 것 | 요약정리·정리노트 Markdown 조립, 출제 계획, 보기 섞기, 용어 상태 올리기만, 빈 답 채점, 복습 대상 | `services/` |
| 중복 제거 (코드) | 요약정리에서 정의를 되풀이한 문장, 다른 용어에 이미 쓴 같은 예시, 정의·요약과 같은 말인 관계, 두 용어가 다 들어 있지 않은 '관계' | AI-2 |
| 이름 맞히기 금지 | 정답이 용어 이름 자체인 문제 (이름만 외워도 풀려서 틀리게 배운 걸 못 잡음). 마지막 라운드에서만 허용해 문제 수는 지킴 | AI-6 |
| 노트 빠짐 검사 (코드, `missing_sentences`) | 선생님 문장(틀린 설명·짧은 설명 포함)을 노트에서 빼먹는 것. 문장마다 글자 쌍 50% 이상이 노트에 반영됐는지 보고, 빠진 문장을 알려 주며 다시 부름 (마지막 시도 제외). 물음과 수업 예고 문장("오늘은 ~ 배울 거야")은 보지 않음 | AI-5 |
| 글투 검사 (코드, `_voice_problem`) | 노트 말투가 평범한 "~라고 하셨다"로 수렴하는 것. 페르소나 글투 표시가 있는 줄이 너무 적으면 다시 부름 (마지막 시도 제외) | AI-5 |
| 노트 소제목 검사 | 개념 설명의 소제목에 수업에서 나오지 않은 3글자 이상 용어를 쓰는 것 → 다시 부르고, 그래도 안 되면 '배운 내용' | AI-5 |
| 정보 분리 | 학생 AI가 용어 정의·요약정리·정답을 보는 것 | 학생 프롬프트에는 페르소나·글투·대화(와 손 든 이유 메모)만 |

- 검사 호출(정의 독립 검사·본문 검사) 자체가 실패하면 그 검사만 건너뛰고 결과를 돌려줍니다 (DEBUG 기록). 같은 정의의 검사 결과는 재사용합니다.

**남는 위험 (0으로 만들 수 없음)**
- **인용은 진짜인데 해석이 틀린 경우.** 테스트 중에도 '학습률'의 정의로 '업데이트 식' 문장을 가져오는 사례가 인용 검증을 통과했습니다. 지금은 정의 독립 검사·본문 검사가 막지만, 둘 다 LLM 판단이라 놓칠 수 있습니다.
- **숫자.** 코드 대조는 원문에 '없는' 숫자만 잡습니다. 원문에 있는 숫자를 다른 대상에 붙인 것, 한 자리 정수, 한글로 쓴 수(열 개), 단위가 바뀐 것(10ms → 10초)은 LLM 본문 검사에 맡깁니다. AI-3 판정·AI-6 출제(정답 독립 검사는 있음)·AI-8 채점·AI-9 보고서에는 숫자 대조가 없습니다.
- 이미지 자료는 AI가 읽은 글이 원본이 되므로, 잘못 읽은 글자는 검증으로 잡히지 않습니다.
- 용어 판정(AI-3)은 명세대로 **방금 보낸 메시지 하나만** 봅니다. 여러 메시지에 나눠 설명하면 `explained`가 안 될 수 있습니다.
- "핵심 용어"는 LLM 판단이라 자료마다 개수가 달라지고, 짝인 개념(전역·지역 최솟값)을 둘 다 고르기도 합니다.
- 학생 질문이 "그리고"로 두 가지를 묻는 경우가 가끔 있습니다 (물음표는 하나).

## 9. 설정 바꾸기 (선택)

`.env`에는 `APP_ENV`, ANTHROPIC_API_KEY, `AI_SERVER_TOKEN` 세 가지만 있으면 됩니다. 아래 값은 `app/config.py`에 기본값이 있어서, **바꿀 때만** `.env`에 `이름=값` 한 줄을 추가합니다. 빈 값(`MAX_PDF_PAGES=`)도 기본값으로 처리됩니다.

| 이름 | 기본값 | 뜻 |
| --- | --- | --- |
| `MODEL_LIGHT` | `claude-haiku-5-5` | 일반 (light) 등급 모델 |
| `MODEL_DEEP` | `claude-haiku-5-5` | 심화 (deep) 등급 모델 |
| `MODEL_JUDGE` | `claude-haiku-5-5` | 판정 (judge) 등급 모델 |
| `ANTHROPIC_EFFORT_LIGHT` | (모델 기본 = medium) | 일반 (light) 등급 깊이 (low/medium/high) |
| `ANTHROPIC_EFFORT_DEEP` | (모델 기본 = medium) | 심화 (deep) 등급 깊이 (low/medium/high) |
| `ANTHROPIC_EFFORT_JUDGE` | `high` | 판정 (judge) 등급 깊이 (low/medium/high) |
| `REALTIME_LLM_TIMEOUT` | 25 | 실시간 API(AI-3·4·8) 시간 예산(초). Django 30초보다 짧게 |
| `BACKGROUND_LLM_TIMEOUT` | 170 | 백그라운드 API 시간 예산(초). Django 180초보다 짧게 |
| `LLM_MAX_RETRIES` | 1 | 형식·근거 검증 실패 시 다시 부르는 횟수 (명세: 한 번) |
| `LLM_MAX_OUTPUT_TOKENS` | 16000 | 호출 한 번의 최대 출력 토큰 |
| `LLM_CONCURRENCY` | 4 | 요청 하나 안에서 동시에 보내는 호출 수 |
| `LLM_GLOBAL_CONCURRENCY` | 8 | 서버 전체 동시 호출 상한. 0 = 제한 없음 |
| `LLM_MIN_INTERVAL_SECONDS` | 0 | 호출 사이 간격(초). 429가 자주 나면 5~10 |
| `MAX_PDF_PAGES` | 50 | PDF 최대 쪽수 |
| `MAX_UPLOAD_MB` | 20 | 자료 파일 최대 크기 |
| `MAX_IMAGE_MB` | 5 | 이미지 최대 크기 |
| `PDF_RENDER_DPI` | 130 | 그림·깨진 글자 쪽을 이미지로 바꿀 때 해상도 |
| `PAGES_PER_READ` | 4 | 이미지로 읽을 때 한 번에 보내는 쪽 수 |
| `MIN_TERMS` / `MAX_TERMS` | 3 / 10 | 용어 체크리스트 개수 범위. 이 안에서 AI가 핵심인 만큼 고름 (150자 미만 자료는 최소 1개) |
| `MAX_RAISED_HANDS` | 0 | 쌓아 둘 손 든 표시 수. 0 = 제한 없음 (기능명세서 기본) |
| `REQUIRE_TERM_NAME_FOR_EXPLAINED` | true | true면 용어 이름이 나와야 `explained` |
| `ENABLE_ANSWER_VERIFICATION` | true | 출제 후 정답이 요약정리로 뒷받침되는지 한 번 더 검사 |
| `ENABLE_DEFINITION_VERIFICATION` | true | AI-1 정의가 근거 청크로 뒷받침되고 그 용어 자체의 정의인지 한 번 더 검사 (LLM 1회 추가) |
| `ENABLE_CLAIM_VERIFICATION` | true | AI-2 요점·관계, AI-5 노트, AI-7 풀이의 본문이 근거와 같은 말인지 한 번 더 검사 (기능마다 LLM 1회 추가) |
| `LOG_RAW_OUTPUT` | true | 검증 실패 로그에 AI 응답 원문(앞 2,000자)을 남길지 (4장) |

- 숫자가 아니거나 최솟값보다 작으면 서버가 켜질 때 바로 오류를 냅니다 (`MIN_TERMS`가 `MAX_TERMS`보다 커도 오류).
- true/false 값은 `true·false·1·0·yes·no·on·off`만 받습니다. `treu` 같은 오타도 켜질 때 오류입니다 (전에는 오타면 조용히 false가 되어 검증이 꺼질 수 있었음).
- `.env`는 실제 키가 들어가므로 공유하지 마세요. 팀원에게는 1장의 변수 이름만 알려 주고, 키는 각자 발급하거나 배포 서버 환경 변수에만 넣습니다.
